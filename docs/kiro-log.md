## 2026-11-27 — Multi-model review catches (physicist + skeptic)
- **Kiro features used:** custom agents `physicist` (read-only physics/units reviewer) and `skeptic` (red-team for the Voice AI explainer) reviewed `packages/engine`; findings became EARS requirements FR-RE-14 to FR-RE-33 in the `risk-engine` spec (tasks 16-28), each backed by a `fast-check` property (P21-P37, fixed seeds) or example test.
- **Catch: NaN inputs scored Safe** (physicist + skeptic). NaN lat/lon/timestamp or satellite el/az produced a NaN score that the level mapping turned into `Safe`. **Fix:** input sanitization drops non-finite satellites; invalid lat/lon/timestamp yields `INVALID_INPUT` and never `Safe`; the level mapper only returns `Safe` for finite scores <= 34. **Req:** FR-RE-14, FR-RE-15. **Tasks:** 16, 17. **Tests:** P21, P22, P23 (`review-fixes.pbt.test.ts`).
- **Catch: invented numbers for missing feeds** (skeptic). Missing GloTEC was scored as 15 TECU and missing Kp was reported as "Kp 0.0". **Fix:** unavailable feeds carry `metricValue: null`, are treated as stale, and no substitute number appears in reasons or text. **Req:** FR-RE-16, FR-RE-17, FR-RE-19. **Task:** 20. **Tests:** P24.
- **Catch: 999 sentinel in STALE_DATA** (skeptic). The staleness reason reported a placeholder age of 999. **Fix:** `STALE_DATA.metricValue` is the maximum age of present stale feeds, or `null` when all stale feeds are missing. **Req:** FR-RE-18. **Task:** 20. **Tests:** P25.
- **Catch: empty feeds scored Safe** (physicist). Empty `satellites`, empty `glotec.cells`, or zero satellites above the elevation mask still produced `Safe`. **Fix:** empty feeds count as stale; zero visible satellites adds `NO_VISIBLE_SATELLITES` and is never `Safe`. **Req:** FR-RE-20. **Tasks:** 18, 19. **Tests:** P26 (both cases).
- **Catch: bad feed ages counted fresh, duplicate staleness code** (physicist). Negative or NaN ages passed the `age <= max` check, and `isAnyFeedStale` duplicated the per-feed logic. **Fix:** only finite ages in [0, max] are fresh; `isAnyFeedStale` delegates to the single per-feed check. **Req:** FR-RE-21. **Task:** 18. **Tests:** P27.
- **Catch: grounding bypass via Unicode and identifiers** (skeptic). Non-ASCII digits (e.g. fullwidth, Arabic-Indic) and U+2212 minus slipped past `verifyGroundedNumbers()`; identifier digits (L1, PRN 12) and range hyphens caused false rejections or wrong signs. **Fix:** digits and signs are normalized before extraction, unmapped `\p{Nd}` digits are rejected, identifiers are skipped, and range hyphens are not read as minus signs. **Req:** FR-RE-24, FR-RE-25. **Task:** 22. **Tests:** P30, P31 (`grounding.pbt.test.ts`).
- **Catch: unit-blind and label-sourced allowlist** (skeptic). Any allowed number matched regardless of unit (a TECU value could be cited as nT), and numbers taken from labels entered the allowlist. **Fix:** numbers with an adjacent unit must match a metric with that unit, at displayed precision (integers exact); label-only numbers are never allowed. **Req:** FR-RE-26, FR-RE-27. **Task:** 23. **Tests:** P32, P33.
- **Catch: replay treated as live** (physicist + skeptic). An unparseable replay fell back to live scoring, the archive timestamp check was lax, and feed ages were not computed relative to the archive time. **Fix:** an invalid replay is `unverified`, stale, carries `replayInvalidReason` and is never `Safe`; a valid replay computes age = archive time - sample time and uses archive time for the post-sunset window. **Req:** FR-RE-22, FR-RE-23. **Task:** 21. **Tests:** P28, P29 (`replay.test.ts`).
- **Catch: explainer wording gaps** (skeptic). The English explainer had no staleness notice, said "live" during replays, fell back silently on unknown presets, and echoed strings without escaping. **Fix:** a staleness notice names each stale feed with its age or "missing" and says "not current"; replay text contains `REPLAY` and the archive timestamp and never "live"; unknown preset ids are disclosed; echoed strings have control characters removed and are capped at 80 characters. **Req:** FR-RE-28 to FR-RE-32. **Task:** 24. **Tests:** P34, P35, P36, P37.
- **Follow-up catch during orchestration** (found while running P34). The deterministic explainer failed its own grounding check for replays and digit-bearing preset ids, because echoed labels and timestamps were extracted as numbers. **Fix:** exact verbatim echo strings are blanked before extraction, and echo digits are never added to the allowlist. **Req:** FR-RE-27, FR-RE-28. **Task:** 24. **Tests:** P34 extended to replays, unknown preset ids and defaulted CUSTOM masks.
- **Scope change: English only** (product decision). Urdu strings, RTL and the language toggle were removed from `apps/web`, `/api/assess` ignores `lang`, and steering/agent docs were updated; Field Mode stays. **Req:** FR-RE-33. **Task:** 26. **Tests:** repo-scan test `apps/web/tests/english-only.test.ts` (no `urdu`, `rtl` or U+0600–U+06FF in app, engine, steering or agents) and the `/api/assess` English-only example test.
- **Known residual risks:**
  - A bare number with no adjacent unit still matches any allowed value of any metric.
  - A short numeric echo (e.g. a replay label "10") blanks every exact standalone "10" in the text.
  - Kp and GNSS replay ages still use the supplied `feedAges`, because those inputs carry no sample timestamp.
  - Medium/low review findings are not yet addressed: lead time not reduced by sample age, Newell coupling saturation, GloTEC grid alignment, quiet-evening post-sunset false positives, and cross-preset monotonicity.
